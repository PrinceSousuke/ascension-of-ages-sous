### Is the Dark-entry grant a problem?

Per USER INTENT the chapter "must NOT itself grant any stage." The Dark entry violates this: it is the
sole world-entry granter of `dark_ages` + the `aoa:age/dark_ages` advancement. This is a deliberate
design choice (gen_j2a.py docstring lines 16-18, `reward_blocks` START_ID branch), but if the roadmap
is to be a **pure** TOC that owns zero grants, this grant must move to a Dark Ages chapter.

**Where it should live instead:** the Dark Ages chapters are `stone_food_and_farming_pressures`,
`stone_water_weather_and_wounds`, and `entering_the_iron_era` (group `12B6640DF4C0DCFE`). The corrected
reveal spine (MEMORY: only 3 Dark entries visible at world entry) means one of the first Dark Ages
quests should own the `dark_ages` + advancement grant as a task-less or first-task reward. The cleanest
home is the **entry quest of `stone_food_and_farming_pressures`** (the true first-visible Dark quest),
mirroring how `entering_the_iron_era` already owns the `medieval_times` grant (line 374). Then the J2A
Dark node becomes a check_quest mirror of that quest like every other node, and J2A owns zero grants.

RECOMMENDATION (propose, do not change): decide with a canon call whether the world-entry `dark_ages`
grant stays on J2A (documented exception, current behavior) or moves to a Dark Ages entry quest so J2A
is a pure TOC. Both are defensible; the code comments treat it as intentional. If it moves, the J2A
Dark node needs a `check_quest` target = whichever Dark quest becomes the granter, and gen_j2a.py's
`START_ID` special-case must be removed.

## 5. Em-dashes — generated, not hand-authored (root cause found)

The E_F audit flagged 55 em-dashes in journey mirror subtitles. Confirmed source: **gen_j2a.py
`lang_entries()` lines 363-364**:

```python
sub = "Age gate — clears when its capstone quest is complete."   # gateway
sub = "Capstone — clears when its quest is complete."            # capstone
```

Live lang confirms 55 subtitle keys carry the em-dash (1 per mirror; the Dark-entry "Granted at world
entry." has none). Because these are emitted by the generator, **editing en_us.snbt alone is not durable
— the next `gen_j2a.py --write` reverts it.** The fix must be in the generator string (replace `—` with
a period or comma per canon: e.g. "Age gate. Clears when its capstone quest is complete."), then regen.

## 6. GENERATOR CHECK — gen_j2a.py can regenerate the target state, with 2 fixes

Dry-run (`python .aoa_reveal_audit/gen_j2a.py`) output:
```

per band: {'Dark': 2, 'Medieval': 1, 'Renaissance': 11, 'Industrial': 7, 'Gilded': 8,
           'Atomic': 11, 'Otherworldly': 8, 'Ascension': 8}

```

This matches the live file exactly (56 nodes, 55 check_quest, all mini-stage/domain-proof capstones
included — Renaissance 11 domain proofs, Atomic 11 incl. all 4 Macabre bosses + Tremorzilla + Geburah).
The `BANDS` list (lines 48-65) enumerates every capstone id explicitly, so it DOES capture mini-stage
capstones, not just age boundaries.

### Does it grant on mirrors? NO (good)
`emit()` only calls `reward_blocks()` inside the `if rid == START_ID:` branch (line 291). Mirror nodes
(line 319+) emit **only** the `check_quest` task, never a `rewards:` block. So regenerating produces the
correct grant-free mirrors. `reward_blocks()` remains defined and is dead code for mirrors — harmless
but worth a comment or removal so a future editor doesn't wire it back into the mirror path.

### modpack_defaults write — CORRECT (doubled config/ nesting)
`WRITE_TARGETS` (lines 34-37) writes both live and
`config/modpack_defaults/config/ftbquests/quests/...` (the doubled `config/config` nesting is present
and correct). Verified: the modpack_defaults copy has 56 nodes, 55 check_quest, 1 astages add, 1
rewards block — content-identical to live (`live.replace(CRLF→LF) == md.replace(CRLF→LF)` = True).

### EOL DRIFT (byte-discipline defect)
- Live `journey_to_ascension.snbt`: **0 CRLF, 1260 bare LF.**
- modpack_defaults copy: **1260 CRLF, 0 bare LF.**
- Content is byte-identical after normalization.

The live file's line endings were flipped to LF (probably during the mass-grant hand-fix). Every other
chapter is CRLF. `detect_eol()` (line 167) re-emits whatever the *current* file uses, so a plain
`--write` today would KEEP the live file at LF. To restore CRLF parity, the live file must first be
normalized to CRLF (or `detect_eol` overridden). This is HYGIENE, not a functional break (FTBQ reads
both), but it violates the pack's CRLF byte discipline and makes future diffs noisy.

### verify_j2a.py — STALE, validates the WRONG design (BROKEN tooling)
`python .aoa_reveal_audit/verify_j2a.py` reports the current correct file as ~110 CRITICAL failures:
- "node ... has tasks (non-empty)" — the verifier expects task-LESS mirrors (old design); the current
  design REQUIRES check_quest tasks. Every mirror trips this.
- "binding dep ... NOT found in any live chapter" — the verifier assumes `dependencies[0]` is a real
  capstone quest id (old design bound the mirror to the real quest via dep). The current design's deps
  are neighbour mirror-node ids (visual TOC lines), and the real capstone id is in the `check_quest`
  **target**, not the dep. So it false-positives on every node.
- It also checks for reward stages on mirrors (expects the re-fire design).

The verifier must be rewritten to the check_quest design: read each mirror's `check_quest` target,
confirm it exists as a real quest, confirm mirrors carry NO rewards, confirm only the Dark entry grants,
and confirm every pack-wide granter has exactly one mirror. Until then it is not a usable guard.
